# OUTSIDER 产品定案 · 卡与额度(2026-08-31)

> 三方(操作者 / Claude / Codex)收敛结果的合并冻结稿。名词预算为零:全部用现有词。
> 本稿定义产品形态与验收标准,不宣称任何未具备的能力(见 §9)。
> 修订规则:与 ADVISOR-CLAIMS-LEDGER 相同——新增条目 + supersedes,不原地改写。

## 0 · 一句话

一张现实系统认的卡,卡上有一个靠记录挣来的额度;每次后果性动作刷一下,毫秒内"通过 / 超额 / HOLD";流水保持打开,直到现实结果关账。

## 1 · 两个答案各贡献什么

- **Codex 的"卡" = 责任对象。** 谁签发(issuer)、谁受理(acceptor)、跟人/角色走、模型可换而责任不可随模型消失、一张卡可交给 Claude/Codex/机器人任何执行方(portability)。
- **Claude 的"额度" = 生命体征。** 靠被记录的干净历史挣、按最坏默认跌、每次后果性提交消耗、n/(n+K) 增长、一个人类零学习成本的数字。
- **合并:卡是名词,额度是数值,刷卡是动词,流水是账。** 证书是死卡;额度让卡活。Visa 类比逐项对齐:卡(签发凭证)+ 额度(挣来的限额)+ "通过"(授权时刻)+ 流水(episode statement)+ interchange(受益侧付费)+ 卡色等级(后期心理层)+ 拒付附件(争议包)。

## 2 · 卡与额度的分工(本稿关键裁决)

- **卡跟人/角色走。** 授权属于人和机构;issuer 拥有授权资格,Outsider 不铸造 authority(C_enabled ⊆ A_proven 不变)。
- **额度跟组合走。** 同一张卡,对 (工作流 × 动作类别 × 资源域) 各有独立额度——如同一张银行卡对 ATM / 线上 / 境外各有限额。无万能卡,无全局总分。
- 战绩记在组合上;责任落在持卡人与 issuer 上。

## 3 · 七个角色(采纳 Codex 版)

Principal(持卡人)/ Issuer(雇主·平台·客户·资源方,真正拥有授权资格)/ Agent provider(Claude、Codex、机器人,仅呈递与执行)/ Acceptor(被改变的系统)/ Witness(独立或 owner 侧结果观察)/ Resolver(挑战·恢复·争议·赔付)/ Outsider(共同规则 + 路由 + 同一 episode 的责任连续性;**永不坐庄**)。

## 4 · 四层能力 = Stage 1–4(卡面必须如实标注)

1. **Recorded** — 完整、不可静默删改的事件流水
2. **Accepted** — 资源 owner 在动作前明确受理具体半径
3. **Protected** — 真实 responder / 恢复承诺 / 资本支持
4. **Network-cleared** — 跨 issuer、acceptor、witness、resolver 的可移植处置

当前诚实状态:Recorded 可交付;Accepted 待第一个真实 acceptor;后两层为 false,卡面必须印 **"Recorded / Owner accepted / No guarantee"**。

## 5 · 钱(采纳 Claude 版)

- **终端用户永不按次付费。** 按指令收保费 = 让持卡人在收银台掏 interchange,品类错误。
- 费用在受益侧:agent vendor / marketplace / agency 按基点;issuer program 年费;(后期)等级与年费心理层。
- 粒度是**后果性提交**,不是指令:session 内可逆动作全部免费区。
- 近期现金流:issuer program 搭建费 + agency 争议包按次。

## 6 · 三个可见时刻(全部界面,不许再多)

看见额度 / **额度涨了**(唯一留存钩子,与查信用分同源)/ 刷卡那一下(通过 · 超额 · HOLD)。无 dashboard、无 feed、无总分、无 DAU 目标。

## 7 · 冷启动顺序

记录器 = 攒流水(**为提额而装,不为安全而装**——事前安装问题自解)→ 争议包 = 拒付附件 → 第一个 issuer program(客户拥有的生产系统 + AI agency 有限部署;Claude/Codex 可互换以证明 portability)→ acceptor 数量 = 护城河 → 2031:agent 互查对方的卡与额度——同一个数字,今天给人看,五年后给机器看。

## 8 · 指标与死亡条件(采纳 Codex 版)

指标:外部 acceptor 数;真实 pre-authorized consequential episodes;owner effect + 外部 outcome 闭环率;provider 切换后责任连续率;异常→恢复时间;owner 是否因闭环扩大下次半径。

**7 天军规:先拿到一个 acceptor 的书面受理规则("满足这些条件的 agent action,我们受理 Outsider;否则 HOLD"),拿不到就不造卡。**

死亡条件:现实资源 owner 不愿把"必须呈递此卡"写进受理规则;或 vendor-native mandate 已足够、无外部方在乎 outcome/recovery 连续性 → 承认它只是日志 SaaS,Visa 论题不成立,停。

## 9 · 不承诺(L10 / L11 边界)

不承诺免责;不承诺撤销现实;Protected 点亮之前不承诺任何赔付;记录不效忠任何一方——唯一承诺:**事后没有任何一方能改写当时发生了什么、谁有什么权限、谁做了什么决定。** 不确定时,HOLD 永远是合法终态。

## 10 · 补遗(2026-08-31 晚,三方第二轮收敛;supersedes 本文措辞,不改结构)

1. **业务对象更正:不是钱,是借来的自主权。** 执行体(Claude/Codex/机械臂/AMR/无人机/车辆)只有能力,没有天然权利;可做什么来自可问责主体的签发 + 受影响世界的受理。钱(MOVE_MONEY)降级为诸多 consequence profile 之一——与既有 core/profile 铁律一致。
2. **额度的底层是分型运行包络**(载荷/力/速度/区域/时窗/次数/收件人数/流量比例…),不可通约、不可相加;"额度"仅是人类前台的压缩语言。统一的不是数字,是动词:签发、预留、收缩、受理、消耗、释放、撤销、挑战、恢复。
3. **双门规则(不可协商):** 现实授权(Outsider 受理)+ 本机安全(native safety READY)同时成立才可执行;本机安全永久拥有无条件否决权。Outsider 永不进入 motion loop,永不替代急停/安全 PLC/功能安全。
4. **提额的宪法与心理:** 历史自动生成"可申请资格"(留存钩子保留),权力扩大必须由 issuer 重新签发、owner 仍可拒绝(C_enabled ⊆ A_proven:proven 是必要条件,签名是充分条件)。
5. **网络语法 = Episode 状态机**(Requested → Delegated → Owner accepted → Native safety ready → Attempted → Effect observed → Outcome pending → Closed / Recovery / Contested)。这是 core;各行业保留自己的安全、证据与 outcome 定义(profiles)。护城河先例:Visa 真正的资产是 ISO 8583 报文标准 + 跨机构清算,不是卡片塑料。
6. **竞争的结构性答案:** 在位者(支付网络/云控制面/身份层/OEM)全部是"门"或"轨",无一持有**事后的未结责任**——因为按最坏默认、押到现实闭环才关账,对他们全部是收入负项。"关账快"是他们的卖点;"不许提前关账"是本网络的产品。空位由损益表守卫,非由无知守卫。
7. **历史类比修正:** Visa 的跨机构受理拓扑 + 空管/铁路(ERTMS Movement Authority)的逐次行动许可 + 黑匣子的事实连续性 + 保险/法律的恢复义务。"AI 时代的银行卡"保留为前台比喻,不作为公司类别。
8. **冻结一句话定位:** 人类第一次可以把行动能力交出去,而不把责任一起弄丢。
9. 事实性待验项:Mastercard Agent Pay for Machines、Skyfire、Visa Intelligent Commerce 等按 Codex 2026-08-31 口径引用,未独立复核;引用前须当次核实(L5 纪律)。
10. **7 天军规不变:** 先拿到一个 acceptor 的书面受理规则,否则不造卡。第一条跨软件-钢铁的 Governed Reality Episode 是网络的落成礼,不是产品的替代品。

## 11 · 第二补遗(2026-08-31 夜;supersedes §6 与 §10 的前台语言,核心结构不变)

1. **从产品核心删除:** deploy gate、MCP proxy、Allow/Deny、审批、策略、审计、回滚——全部属于"改变运行"(厂商地界),按既有手术刀出局。卖这些 = 与在位者无本质区别。
2. **分界线冻结:** agent safety 回答"能不能让它做";Outsider 回答"做完以后,这件事由谁负责到底"。
3. **消费者前台 = 订单语法**(取代卡/额度/弹窗作为人话层;卡与额度退为后台账户结构):下单(事前封印的商业化名——验收标准随单冻结)→ 签收/退单/售后(五终态的一一对应:SAFE_DELIVERY=签收;VERIFIED_DELIVERY_UNATTRIBUTED=签收不认功;CONSERVATIVE_STOP=主动退单;UNFINALIZED=未完成;containment=拦截)→ 我的订单(episode 流水)→ 申请平台介入(争议包)→ 售后与运费险(恢复义务与未来 Protected 层;运费险先例:按单微保费以购物选项形态被十亿人接受,推翻"无人按次付保费"的旧反对)。
4. **换了 Agent 也不能赖账** = 责任跟订单走,不跟 runtime 走(§2 原则的消费者表述)。
5. **结构护城河的消费者版:** "Done"是厂商 KPI,"退"是其损益表毒药;"平台介入"天然要求不卖货的第三方。
6. **一句话(用户版,冻结):** AI 和机器人干的每一件事,都像一张订单:能验收,能退,有售后,换了 AI 也不能赖账。
7. **五字版:** AI 的活,能退了。

## 12 · 终稿(2026-08-31 深夜;三方最终收敛)

1. **公司定义:** Outsider 是自主工作的订单与售后网络。厂商的 Done = 提交交付;资源所有者验收或售后真正完成,订单才关闭。
2. **资金四层,逐单明示,不许合并成"Outsider 保障":** ①服务商准备金(第一阶段唯一开启层,托管持有)→ ②服务商保证金(决定可承接敞口)→ ③Outsider 先行垫付(信用业务)→ ④持牌保险(低频大额)。救济优先于钱:回滚/重做/人工接管/维修在前,退款补偿在后。
3. **垫付防火墙(入宪):** 赔钱的人不能兼任验收裁判。验收标准随单冻结,判定由可重算规则执行,争议走独立 resolver;**Outsider 自有资金在场时,其判定权自动让位。** 京东的售后体验,淘宝+支付宝的席位;永不自营,永不履约。
4. **追溯权 = 程序性权利**(谁委托/谁接受/几次尝试/改变了什么/谁判定/谁欠着什么/为何关单),不含商业秘密、个人数据、chain-of-thought;原始数据留在各节点,Outsider 提供可验证的必要事实。
5. **北极星(冻结):** 智能可以换,机器可以换;订单不能消失,售后必须有人负责到底。
6. **第一张订单规格(取代一切路线图):** 一个低额、可验证、可恢复的垂直场景;真实外部验收方;真实恢复义务;明示的准备金来源(Provider Reserve ¥X)。7 天军规的开场白:"我们交付的每一件 AI 干的活,都带验收单和售后。不对,退。"

## 13 · 产品结构终稿(2026-09-02;三方收敛,supersedes §11–12 的前台语言,不改资金与防火墙条款)

1. **三层结构:** 用户产品 = 现实账户(持有"外部世界已承诺、尚未解除的结果");核心商品 = 结果承诺;底层 = 履约、资源、独立验收与恢复网络。产品是用户持有承诺的方式,网络是承诺能成立的原因——二者不再是两个东西。
2. **交易瞬间 = "接住",取代"封印"。** 愿望 → 方案 → 只有当执行方、资源所有者、独立确认方式、恢复方全部签入,才成为承诺。等价于支付网络的"授权成功"。此前一律显示"尚未被接住",不得假装成订单。
3. **接住必须显示押注:** 谁接、押了什么(准备金 / 保证金 / 持牌保险)、封顶多少。无押注只能显示"已受理",不得显示"已承诺"。资金四层与垫付防火墙(§12)原样适用。
4. **第一天的接住方:** 数字品类由 Outsider 自营 runtime 接住并押自有准备金;物理品类先签一个真实持证承接方。宁可九类显示"暂无人接",不得有一类假接。
5. **一个对象,三个视图:** 此刻(首页只显示最值得关注的一件现实,其余折叠为一句)/ 账(按差额组织的对账表,§v6)/ 地(资源所有者签入入口:哪些资产允许被碰,§v7)。
6. **默认交互 = 在两个未来之间选择**("保持预算·11:00 可用" vs "加 ¥600·保持 08:30")。凡需用户介入之处,一律长成这个形状;不出现工作流控件。
7. **用户的两个核心动作:** "让这件事成真" / "这件事并没有真的发生"(重开承诺,而非客服工单)。
8. **机制判据(冻结):** 工作流约束自己,机制约束别人。一项功能若把"Outsider"换成"我的 Agent"仍成立,即非核心;若换掉执行 Agent 后承诺、义务、结算、申诉仍成立,才是 Outsider 的东西。
9. **用户体感三件套(第一单必须同时兑现):** 接住时价格固定;真实对手方按承诺出现且不重新讲价;失败时押注的钱自动流动。任一项靠人肉兜底,即仍为加强版 Codex。
10. **竞争判断:** 实验室结构性倾向甩责任而非接责任(平台物理);真正对手是已有供给网络+托管+先行赔付文化的平台(美团、京东服务+、万师傅)。可守之地:跨数字与物理的同一张承诺,与证据门控的放款。第一单不选在其地盘上。

## 14 · 三层结果网络(2026-09-04;supersedes §13.10 中"受理方优先=让节点采用我方格式"的表述)

0. **更正:** 受理格式会被行业标准化(UCP / AP2 / A2A / OIDC-A),无人能拥有格式。正确位置 = 在公共标准之下运营清算与预留(DTCC / SWIFT 之于公共结算标准)。已核实:AP2 明确将争议解决、留存、检索排除在规范之外,并预设"网络仲裁方"存在——标准不填席位,标准预设席位。
1. **第一层 · Outcome 语言:不自建协议。** 为 UCP / AP2 / A2A 编写其明确 out-of-scope 的扩展(结果状态、恢复义务、争议材料、长期留存),做参考实现。开放、免费,用于采用与数据。
2. **第二层 · 恢复期权市场(破局层):** 用预先预留的替代路径(可取消预订、库存 hold、容量 option、第二通道)替代现金保证。后果:资本轻;骗赔失去动机(救济为实物路径);Codex/超级 agent 每新增一个接口 = 新增一条可预留路线(其进步为顺风)。先例:电网备用容量市场。目标函数:min(主路线成本 + 期权成本 + 资本成本) s.t. P(按期达成) ≥ 目标可靠度,CVaR95(用户损失) ≤ 上限,**主路线与恢复路线不属于同一失败域**——相关失败定价为本层唯一不可复制的 IP(共享因果 / 失败相关性数据地基的用途)。
3. **第三层 · COMMIT:** 仅当主容量、恢复容量、见证、责任、资金、争议路径全部闭合时给出;§12 资金四层与防火墙原样适用。
4. **漏斗:** 所有任务进第一层(采用、数据、容量);中等风险任务购买期权(收入);高价值任务购买 COMMIT(利润与资本)。撤回"只做 5% 很贵的市场"的公司级表述(仅对 COMMIT 层成立)。
5. **与超级 agent 的关系:** 编排层竞争、执行层合作;用户用 Codex,Codex 在需要形成/恢复/承诺现实结果时调用 Outsider。Outsider 不绑定执行者。
6. **节点架构:** 凭证留在本地 Outsider Node;网络只交换 tender / reservation / evidence / obligation;中央只做清算与风险计算,不持有账户(消解令牌集中持有的攻击面)。
7. **第二层起步约束:** 期权仅在容量本可预留、可取消处成立——云资源、旅行住宿、物流舱位、仓储容量、平台预留工时;首个期权试点不选物理施工类。
8. **判据不变:** Codex 变强,Outsider 应受益而非受损;任何使其受损的功能即为竞速,删除。
9. **期权的定义(收紧):** 零成本的备用路径(可取消预订、备用账户)= 双重预订 = 工作流,且会被供给方封杀;**只有付费且对方承担持有义务的备用容量才是期权。** 第二层的真实难题是造出愿意卖 hold 的供给侧(双边市场冷启动),不是 CVaR 公式。
10. **覆盖边界:** 期权覆盖个体失败(单一供给方掉链子),不覆盖系统性失败(暴雪/区域断网/平台宕机——备用容量同时变忙或天价);系统性部分只能由第三层资本与保险承接。"不同失败域"处理相关性,不处理稀缺,二者分开写。
11. **采用的因果方向:** 第一层的采用由第二、三层拉动,不由开放性推动。先在窄场景把期权做真,语言跟着期权走出去。
12. **交割形式即法律形态:** 期权以替代路径(实物救济)交割 = 服务合同;以现金交割 = 保险/衍生品,需牌照。"救济优先、现金最后"是第二层无牌可开的前提,不是偏好。
13. **独立见证网络不是可选出路,是三层的脊柱:** 期权触发条件若由执行方自报,第二层的自动执行即建立在可操纵信号上。见证为三层共同前提。
14. **第二层第一里程碑:** 一个供给方签下一份收费、带持有义务的备用容量合同。场景限于容量本有期权形态处(云算力、物流舱位、平台预留工时)。此前第二层为公式,此后方为机制。
