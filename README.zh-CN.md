# Outsider

[English](README.md) | [简体中文](README.zh-CN.md)

**面向多 Agent 与现实资源的结果协调、失败恢复和责任记录基础设施。**

Outsider 的愿景很简单：用户说出希望发生的事情，以及愿意为完成它支付的价格；软件组织资源，在失败后继续恢复，并持续处理尚未完成的责任，直到结果得到解决。

这个仓库开放实现这一愿景的底层：结果规划与持久执行、证据与认证、主体及委托记录、恢复协调，以及定价、担保、索赔和清算研究模块。HapNex 是单独的应用层，其产品界面和业务流程不在本次开源范围内。

## 可以拿它做什么

- **持续运行的 Agent 工作流。** 把明确的结果编译成 `OutcomeProgram`，执行依赖图，中断后继续，在主路线失败时启用已绑定的恢复路线。
- **现实资源协调。** 根据已提供的能力、成本、时间窗口和共享容量选择方案，通过资源所有者控制的 adapter 执行，并通过配置的观察路径验收。
- **多 Agent 共同操作资源。** 用租约、fencing token、版本检查和幂等命令协调对同一页面或资源的访问；外部动作结果不明时，先核对实际状态，再继续下一条命令。
- **证据与责任连续性。** 保存来源绑定的观察、主体和委托关系、每次尝试、争议及剩余义务。换一个 Agent 或供应方后，原有记录仍然存在。
- **风险与清算研究。** 在明确边界内研究经验整理、损失与敞口、非约束报价、担保门和索赔流程。

例如，多个个人或公司 Agent 需要修改同一个共享页面。协调器负责排队并拒绝过期写入，页面所有者的 adapter 检查授权并真正执行修改。这一模式也可以用于设备。每一种页面或设备仍需要自己的实际控制与状态核对接口。

## 目前的实现

| 部分 | 当前仓库提供的能力 |
| --- | --- |
| 结果规划 | 基于声明的动作和资源做有界世界状态规划；将自然语言目标匹配到能力目录，再编译成现有程序格式。 |
| 持久执行 | 主执行、恢复和见证绑定，依赖图执行，持久操作标识，中断恢复，观察和资源生命周期处理。 |
| 共享资源 | 面向合作 Agent 的通用协调机制，以及资源所有者控制的执行边界。具体页面和设备需要接入 adapter。 |
| 证据与责任 | 本地完整性校验，来源与生命周期复核，主体和委托记录，网络接入一致性检查，以及持久义务记录。 |
| 定价 | 研究与影子分析。Stage 2 报价出口返回 `NON_BINDING_ABSTAIN`。 |
| 担保与清算 | 本地核算、来源绑定门和候选索赔流程。商业承保、资金托管、付款、裁决及最终免责需要实际外部机制接入。 |

开发记录中已有一次数字发布任务经历主路线失败、恢复路线执行、外部观察和资源释放。这说明对应 adapter 组合实际运行过。开放测试提供可重复的本地检查，默认不需要云账号，也不会移动资金。

## 开始使用

使用 **Node.js 22 或更高版本**，建议 Node.js 24 LTS。

```bash
npm ci
npm test
npm run demo:shared-page -- --once
```

可以先读并运行规划器与持久执行器的测试：

```bash
node --test test/outsider-world-state-resource-planner.test.js
node --test test/outsider-durable-outcome-program-orchestrator-v1.test.js
```

测试和示例使用显式 fixture adapter。运行真实供应方动作时，需另外配置 adapter、提供对应资源所有者的授权，并明确选择执行动作。凭证和真实运行目录应留在版本控制之外。

这是面向源码贡献的仓库。`src/` 使用 ES modules；带版本号的文件保留既有契约，新的组合可以在此基础上演进。组件地图见[架构说明](docs/ARCHITECTURE.md)，贡献入口见 [CONTRIBUTING.md](CONTRIBUTING.md)。


共享页面示例和接入接口见[共享资源协调](docs/SHARED-RESOURCE-COORDINATION.md)；来源重放与数据许可见[数据与证据](docs/DATA-AND-EVIDENCE.md)。`npm run test:research` 运行额外的研究测试，需要准备各模块说明中的来源数据。

## 两条相互配合的主线

执行栈分三层：

1. **Outcome OS：** 定义、协调、观察和重放一个结果。
2. **Formation 与 Recovery：** 绑定可用能力及备用路线，明确触发、到期、成本和启用条件。
3. **Outcome Commitment：** 在所需预留、授权、观察和资金条件齐备时，接受有明确边界的结果承诺。

证据到清算则是另一条处理链：

| 阶段 | 用途 | 当前边界 |
| --- | --- | --- |
| 0.5 — MEASURE | 固定任务契约，记录 Agent 执行证据，在已配置宿主上提供生命周期监督。 | 控制范围取决于精确宿主的 hooks 与真实运行一致性。 |
| 1 — ATTEST | 校验完整性、来源重放和证据生命周期。 | 有效签名绑定某个密钥的陈述，不自动证明机构资格。 |
| 1.5 — CURATE | 按来源、权利与复用条件整理经验。 | 接收与整理不自动授权训练或金融用途。 |
| 2 — PRICE | 研究行动前风险、敞口、损失和价格。 | 当前输出为研究和非约束结果。 |
| 3 — GUARANTEE | 检查来源绑定、请求核算和一次性能力门。 | 不签发保单，不建立托管，不转移资金。 |
| 4 — CLAIMS / SETTLE | 保存索赔、争议、回执与清算候选。 | 当前出口保持 `HOLD`，不执行付款或最终关闭责任。 |

这些名称描述组件分工和发展方向。目前没有运营覆盖任意现实目标的全球金融清算网络。
