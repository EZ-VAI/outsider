# 小步快跑与完整组网进展的区分 · 2026-09-06-r25

本修订澄清 [r24](OUTSIDER-OPEN-NETWORK-PRIORITIES-20260906-R24.md)，不是推翻已有路线或禁止简易任务。

## 方法不变，进度口径改变

**小步快跑是正确方法。** 在可行范围内选小任务，尽快取得真实接口和结果证据，
可以降低未知、验证机制、定位错误。不能因为 Outsider 世界观大，就只做宏大设计、不交付可运行切片。
也不能把一个小切片的成功外推为完整产品、跨行业覆盖或大型复杂任务已解决。

每个工程切片写清：要消除的未知、通过条件、实际结果、可复用增量、未证明内容以及下一工程门。
验证已回答问题后推进下一缺口；相同切片仅因必要回归、真实故障、性能问题或生命周期收尾而重跑。
不要为了展示成功而不断换相似样例，也不要为了反对小样例而跳过必要工程。

## 每轮分开汇报

| 层级 | 可报告的真实增量 | 不可外推 |
| --- | --- | --- |
| 单点可行性 | 一个 API、预留、恢复或验收机制确实可用 | 不能据此说整单/全网已成立 |
| 可复用能力 | 接入原 Node/编译器/执行器的新协议、发现、组合或恢复能力 | 不能把新增文件/节点数量当作覆盖 |
| 完整产品 | 特定边界内，从用户目标到形成、执行、独立验收及收尾的真实闭环 | 不能据此宣称任意任务、地域或供应商覆盖 |
| 全网组网进展 | 可交易路线、已认证可调用范围、真实报价/ETA/容量、形成耗时与复用效果 | 文档、注册目录、测试库存和提供方 ACK 不是供给或结果 |

没有新增可交易路线或完整产品能力时明确报告零；不编造工程总完成百分比。

## 保持同一架构

开放目标理解 → 需求/依赖/验收/恢复图 → 分布式真实发现与接口理解 → 有来源的候选比较
→ 原 world-state planner/compiler 和 OutcomeProgram/Node → 原生执行、独立验收及恢复/收尾。

模型理解和探索负责处理开放世界，可靠代码负责连接与调度，不要求穷举任务或供应商。
身份委托、原数学/因果/精算与数据地基按具体用途接入；不另建一套通用调度器，
不把演练办公室/工厂/采购场景变为唯一垂直产品，不让聊天或鼠标逐单操盘。
覆盖不以创始人账户或员工 outreach 定义；供应方一次授权和合法交易仍须真实成立。
金融 MVP 保持模拟，付费项暂存，不阻塞非金融主线。
