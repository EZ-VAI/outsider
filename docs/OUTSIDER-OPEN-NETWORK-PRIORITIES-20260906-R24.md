依据用户本轮提醒：不否定既有交付、恢复与责任工程，但停止以小样例重复成功为主要进度。
这份修订调整后续工作，保留 r23 及更早记录、授权、承诺语义和未完成生命周期义务。

## 核心工作单位

不是“再完成一个固定任务族”，而是“一个此前未预设的完整目标，新增多少可发现、可组合、可实际执行的资源路径”。
线上和线下同等重要；办公楼/工厂是复杂度提醒，不是把产品硬编码成办公服务或工厂服务。

模型负责开放目标理解、跨域资源搜索、接口理解与方案生成；软件负责有来源的接口绑定、
并发调度、依赖、持久状态与执行。代码不能穷举现实，但模型也不能把假设变成库存、报价或验收。
卖方文档可公开而交易仍需合法买方账户、合同或资源所有者授权；这与逐单员工 outreach 不同。

## 重新排序

1. **开放需求图（当前主线）**：不先在三个任务族中分类。保留完整目标、依赖、联合验收、
   恢复需求和未知事实；将未覆盖部分变为发现工作，不把任务简化成已支持的小样例。
2. **分布式发现与接口理解**：接用户/端侧 Node、已有账户、公开市场、官方 API/MCP、
   开放容量。提供方名单是可替换输入，不是代码中的世界边界。文档搜索、认证门槛、
   地理服务范围和交易能力分别判断。共享查询去重，独立查询并发，保留未搜完的队列。
3. **动态组合**：从实际报价、ETA、容量和责任接受构造候选动作，交回已有 world-state
   planner/compiler 与 OutcomeProgram runner。没有来源的参数保持未知，不能补零成本/假时长。
4. **通用执行扩展**：按真实目标发现的缺口优先开发协议适配和数据转换，避免为每个场景另建调度器。
   接入新接口后应服务多个未来任务，不仅服务一次 demo。
5. **网络复用**：保存用户许可范围内的已验证交易路径、可撤销容量与履约结果，形成共享资源调配网络。
   不以创始人熟识供应商数量或买方账户单入口定义覆盖。

原有小链维持少量回归；修复会影响真实任务的故障、收尾当前资源、补必要见证继续做。
但不能再次把“新增一轮数据库/发布页演练”排到开放组网主线之前。
金融在 MVP 继续模拟，无需资本/付费接入阻塞非金融能力。

## 本轮实现

`src/outsider-open-resource-demand-graph.js` 增加开放需求与发现前置层，复用原模型解释器。
模型生成完整依赖 DAG、验收、恢复与查询；能力目录只提示可复用积木，不限制目标范围。
发现以可替换函数接入，跨需求共享查询去重，限量并发与未搜索队列分开记录。
未知节点保留，失败的发现分支不抹掉其他分支。

`scripts/outsider-open-resource-demand.mjs` 是本轮原生运行入口：
现有产品模型 → 文档地址候选 → 原有 public HTTPS transport 的无凭证 GET → 有来源的待接入清单。
地址由模型提出，GET 只证明文档可读取，不证明该资源匹配或已经取得交易能力。
当前这个入口**还不是搜索引擎发现、接口自动理解、真实报价或执行入口**；保留查询以待接入原 Brave/发现联邦。
这些界限用于如实衡量进度，而不是把陌生任务再次整体拒绝。

3 项聚焦测试：陌生需求不丢失/共享发现去重、拒绝依赖环、保留超预算发现与失败分支。
不新增小数字订单，不执行现场工作、设备控制或购买。

### 一次复杂目标实际运行：不予提升为供应发现能力

使用假设 30 人办公室目标，实际调用产品内原模型解释器，生成 **9 个需求节点 / 23 条依赖**。
覆盖场地条件、设计、主备线路、LAN/Wi-Fi、电脑、桌椅、收货/安装、独立联合验收和证据恢复。
保留 18 个不同查询，当前预算运行 12 个发现回调，另 6 个明确保留未处理。
但模型提出的许多网址是通用/监管指南，不是可交易接口；**本轮新增可交易路线数为 0**。

首次模型进程失败；一次有界重试后解释耗时 **104.710 秒**，不是秒级形成已成立。
初版公共 GET 调用漏传既有传输所需选项，修正后重用相同解释，未重新调用模型；
生成 `result-r2.json` 并链接旧结果 hash，不覆盖初版记录。
后继运行有 4 个原生公共读取，发现阶段 **802 ms**；仅 D1 文档 HTTP 200，仍不是新增现场供给。
不能把缓存解释的 1 ms 冒充第一次模型编译速度，也不能把文档读回当成交付能力。

因此：当前模型网址猜测只保留为辅助线索，不作为主要发现路线。下一实施项明确调整为
将已存在的 `outsider-brave-search-route-discovery-adapter-v1.js`、
`outsider-mcp-registry-discovery-adapter-v1.js` 及其发现联邦接到开放需求图，
让实际搜索结果驱动供应候选，并保留不匹配/需要账户/合同/无地域证据的原因。
MCP 注册信息也只证明有连接器记录，不能证明卖方库存、设备所有权或现场容量。

## 可执行覆盖候选，而非已接入供给

- [Field Nation Client API](https://developer.fieldnation.com/docs/rest-api/introduction/) 提供现场工作单生命周期接口。
  [前置条件](https://developer.fieldnation.com/docs/getting-started/prerequisites/)要求买方账户和集成合同；
  此路线暂列 `ACCOUNT_AND_INTEGRATION_CONTRACT_REQUIRED`，不是免费匿名可立即调用的供给。
- [Cisco Meraki API](https://developer.cisco.com/meraki/api-v1/getting-started/)提供网络与设备管理入口，
  仍需目标网络授权；不能把管理 API 当成网络线路已安装或现场设备已供货。
- [Jamf 设备清单 API](https://developer.jamf.com/jamf-pro/reference/get_v1-computers-inventory)
  可作为既有设备/管理平台接入候选，不等于新电脑采购与送达能力。

没有签集成合同、发出工作单或向卖方提交用户资料。路线门槛不是永久阻塞：继续寻找替代入口。

## 后续进度指标

- 完整目标中已找到可交易路线、已认证可调用、已预留的必需资源比例，分别报告。
- 陌生需求保留率、未解决依赖/联合验收/恢复缺口，不能用节点总数冒充覆盖。
- 形成耗时按模型理解、发现、接口读取、报价和容量锁定分别计时。
- 查询复用、原生调用并发和每单模型/API成本；不能只报告执行阶段 729 ms。
- 接入一次可复用多少能力、任务及独立提供方；同一公司多接口不算多个故障域。
- 每单 Outsider 员工参与次数，目标为零；开发过程 onboarding 不混入逐单运行。
