# Stage 1.5 causal-judge hypothesis-survival instrument

Status: locally complete policy-conformance instrument; zero external authority
and zero measured-survival claims in the current pilot.

The implementation is in `src/outsider-causal-judge-survival.js`. The verifier
CLI is `scripts/stage15-causal-judge-survival.mjs` and the adversarial suite is
`test/outsider-causal-judge-survival.test.js`.

## What “survival” means here

A semantic causal hypothesis survives only when every test frozen in that exact
hypothesis version survives its preregistered intervention-consistency rule.
The instrument does not let the model, registrar, assignment operator,
execution operator, outcome assessor or adjudicator add or remove a test after
seeing an outcome.

There are two deliberately separate outputs:

- `localConformanceDenominator` counts correlation-safe evidence components
  whose complete chain satisfies a pinned configured policy;
- `authoritativeMeasurement.denominator` is fixed at zero until externally
  governed reality and institutional independence are established outside this
  module.

Thus a locally generated test key can exercise the whole interface, but it
cannot manufacture a real measured survival rate or an independent authority.
The formal zero-evidence pilot reports `proposedHypothesisBundles: 0`, local
eligible denominator `0`, and authoritative measured denominator `0`.

## Reality, evidence authority and permitted use are independent

The source axes keep three different questions separate:

| Axis | Question | Examples |
| --- | --- | --- |
| `sourceReality` | What environment produced the record? | `REAL_PHYSICAL`, `REAL_SOFTWARE`, `CONTROLLED_REAL_APP`, `SIMULATION`, `SYNTHETIC` |
| `evidenceAuthority` | What verification/adjudication backs it? | prospective source replay with configured-role separation, retrospective source replay, publisher-declared, metadata-only, self-reported |
| `permittedUse` | What may this exact evidence support? | survival measurement candidate or mechanism candidate only |

`evidenceTiming` additionally distinguishes prospective, historical, public
retrospective, metadata-only and simulation-only evidence.

`SOURCE_REPLAYED_PROSPECTIVE_CONFIGURED_ROLE_SEPARATION` means only that the
pinned local policy uses distinct configured keys and organization commitments
for its roles and that the exact prospective sources replay. It deliberately
does not claim institutional independence; every bundle keeps
`institutionalIndependenceEstablished:false`.

A public robot failure record may therefore remain a real physical empirical
observation while contributing zero to a causal-survival denominator. Calling
its permitted use descriptive or mechanism-only does not relabel the event as
synthetic or unreal. Historical, public, metadata-only and simulated records
can create source-replayed mechanism candidates, but the code fixes their
denominator contribution at zero.

## Required prospective evidence chain

A local measurement candidate must replay all of the following:

1. a pinned Ed25519 governance policy with five distinct human/institution role
   keys and five distinct organization commitments;
2. a signed, immutable, semantically versioned hypothesis registration before
   both assignment and execution;
3. all planned intervention/control tests, falsification rule, population,
   semantic identity and correlation roots frozen in that registration;
4. a separately signed randomized assignment generated by
   `SHA256_BALANCED_BLOCK_V1`, with at least the preregistered number of units in
   each intervention and control arm;
5. the exact randomization bytes and canonical assignment ledger bytes;
6. a complete signed execution containing every assigned unit and every planned
   test, bound to a closed full-source manifest;
7. exact replay of all manifest bytes, including randomization beacon,
   assignment ledger, execution trace and outcome observations;
8. a signed outcome assessment after execution by an independent role,
   covering the complete planned test set; and
9. a separate signed adjudication after the assessment by another independent
   role, binding the same hypothesis, assignment, execution, outcome and source
   manifest.

Policy creation rejects a model as any signing authority. It also rejects a
reused role key or organization, so one signature identity cannot register,
execute and then evaluate itself. A hypothesis may be model-proposed, but only
a separate pinned registrar can preregister it and the model receives no path
to sign its own outcome or adjudication.

These checks establish configured-policy conformance. Bytes and signatures
cannot by themselves prove that a claimed organization is institutionally
independent or that claimed real-world acquisition actually occurred. Those
remain external evidence and authority requirements.

## Full-source replay

The source manifest records, for every source object:

- a safe source ID;
- its protocol purpose;
- media type;
- raw-byte SHA-256; and
- exact byte length.

Measurement candidates require all four minimum purposes:
`RANDOMIZATION_BEACON`, `ASSIGNMENT_LEDGER`, `EXECUTION_TRACE` and
`OUTCOME_OBSERVATIONS`. Verification refuses a missing object, an additional
unbound object, a changed byte, a changed length, a non-canonical assignment
ledger or a source-purpose omission. A structural hash-only check is not
reported as source replay.

The randomization verifier recomputes balanced assignment from the exact beacon
bytes, test ID and unit hash. The canonical assignment source is recomputed
byte-for-byte. This closes the local substitution path; it does not claim the
beacon was administered by an external institution.

## D1 and correlation-safe counting

The report discloses:

- the number of submitted bundle occurrences;
- unique evidence hashes;
- exact duplicate hashes and their collapsed counts;
- unique locally eligible bundles; and
- connected correlation components.

Bundles join the same component when they share a semantic hash, identity hash
or disclosed correlation root. A component contributes at most one local
conformance denominator unit. If correlated bundles disagree about survival,
the entire component returns `ABSTAIN_CORRELATED_OUTCOME_CONFLICT` and
contributes zero. Exact duplicate occurrences remain visible under D1 rather
than silently increasing the numerator or denominator.

Semantic and correlation hashes still depend on the preregistered normalization
process. The local instrument can verify their immutability and deduplication;
it cannot prove that an external ontology or institution chose them correctly.

## Fail-closed boundary

Any missing or invalid hypothesis version, time ordering, planned test,
intervention/control arm, source byte, signature, role independence binding,
outcome or adjudication produces `ABSTAIN` and denominator contribution zero.
Every verification result fixes:

- causal experience units to `0`;
- learning permission to `false`;
- `PRICE` to `false`;
- production use to `false`; and
- authoritative measured survival to `false`.

The instrument does not train a model, issue CEUs, price risk, authorize a
guarantee, settle a claim or perform a production action.

## Verifier CLI

The CLI accepts a JSON envelope:

```json
{
  "policy": {},
  "bundles": [],
  "mechanismCandidates": [],
  "createdAt": "2031-02-01T00:00:00.000Z"
}
```

and a source map whose paths are relative to the source-map file:

```json
{
  "random-run-1": "sources/random.bin",
  "assignment-run-1": "sources/assignment.json",
  "trace-run-1": "sources/trace.ndjson",
  "observations-run-1": "sources/observations.ndjson"
}
```

Run:

```sh
node scripts/stage15-causal-judge-survival.mjs \
  --input /path/to/input.json \
  --source-map /path/to/source-map.json \
  --pinned-governance-key-id ed25519:sha256:...
```

`--out FILE` writes canonical JSON using no-clobber semantics. Absolute source
paths and paths escaping the map directory are refused. The output is rebuilt
and verified before it is emitted.

## Adversarial coverage

The focused suite covers:

- missing governance pins;
- model signing authority and same-key/same-organization role collapse;
- assignment before preregistration;
- missing control and incomplete planned-test sets;
- exact-source byte substitution and missing source objects;
- hypothesis, outcome and time-order mutation;
- an adjudication signed by an unpinned fake adjudicator;
- D1 exact duplicate injection;
- shared semantic/correlation roots; and
- conflicting outcomes inside one correlation component.
