## 1. 产品原则：哪些不变，哪些进一步明确

1. **交付对象是状态，不是动作列表。** 采购、代码交付、部署、预约、设备配置和现场服务同等属于能力来源。订单成功不等于目标成功；最终验收必须对应用户的目标。
2. **一张订单即时形成一张临时网络。** 起步不要求建立供应商数据库、入驻或员工 outreach。优先复用原生交易入口、用户账户、资源所有者节点、官方 API/MCP/CLI 和既有市场。
3. **Agent 是生产能力，也是产品入口。** 强模型可以负责目标理解、陌生接口探索、方案生成和有边界的执行。零员工介入不等于零模型参与。开发对话逐步代办不得算产品自主完成。
4. **机器接口优先，通用探索补充。** 不等待全网 MCP 开放，也不先为每个网站手写适配器。稳定、高频路径固化为原生调用；UI 可作为受授权且有时延、成本记录的补充，不成为核心生产路径的唯一实现。
5. **入口和执行不依赖创始人的终端。** 客户端、用户 Node、机构节点、托管节点和资源所有者节点均可参与。设备可以在私网内执行，不必暴露到公网。创始人账户只是研发环境，不是所有订单的唯一入口。
6. **正常订单中 Outsider 员工触碰目标为 0。** 研发、公司级合作与账户配置不等于逐单代办。外部技师、司机、资源所有者和持牌争议处理者可以是参与方；如发生内部人工介入，保留记录并计为自主产品失败，不能隐藏为系统成功。合法投诉和争议权利不能因自动化目标被取消。
7. **资本保障是产品层，不是全世界每个动作的保费。** 普通执行可以先上线；资金支持的结果承诺仅在相应范围真实成立时提供。第三方损害、设备权限与用户未获结果，是不同问题，赔款不授予行动许可。
8. **Outsider 不以成为完整保险公司为默认路径。** 优先设计与外部合格承保、资本和支付合作方的接入。赔付主体、责任缺口和法律角色必须明确，合作意向不等于已绑定保障。
9. **不以“大厂一定不做”支撑战略。** 差异来自跨提供方履约、恢复、损失数据、真实资本关系及持续兑现记录；后续再发展需求汇聚与共享资源安排。
10. **所有地基按用途接入，而非整仓迁移。** 数学规划用于约束求解，因果研究用于干预效果，精算用于损失与资本，数据工程用于可用反馈，权限用于真实执行。不得把模型分数、研究结果或字段齐全当成外部事实。
11. **一个 Outsider 入口，不是每个用户逐商户开户。** 用户身份、向供应商采购的买方身份、资源权利人必须分开。普通可采购任务优先使用本单游客会话、获准的平台/合作方采购关系；用户已有资产才按需连接本人权限。平台级一次性接入可以存在，但不得成为逐单员工代办；不能默认后台替用户秘密注册账户。统一入口包括报价确认、订单跟踪、取消和售后，不仅仅隐藏登录页面。创始人账号与浏览器会话不是所有用户的交易身份。

既有身份图继续使用：`PrincipalEpoch → AccountableDeployment → Runtime/Embodiment → Delegation → Episode → Attempt`。继续保持 `C_enabled ⊆ A_proven`，并把行动后果限制在已承诺证据和责任范围内。Outsider 不替代厂商原生安全控制、PLC 联锁或专业执业要求。

## 2. 目标产品结构

### 2.1 三个产品层，使用同一条执行链

| 产品层 | 用户得到什么 | 不能声称什么 |
| --- | --- | --- |
| L1 通用 Outcome 执行 | 理解目标、形成计划、调用真实能力、持续跟踪与验收；明确费用和授权 | 没有资本保障时，不宣称失败损失已被承保 |
| L2 临时组网与恢复 | 按订单获取主路线、实际可调用的替代方案及相应恢复权利 | 搜索结果、购物车和可用时段不等于已预留容量；可恢复不等于已保险 |
| L3 资本支持的结果合约 | 在 L1/L2 之上，明确失败触发、约定赔偿、承责主体与实际生效的资金保障 | 不承诺穷尽所有未来隐性损失；赔付完成不等于状态已交付 |

L1 的产品化是目标范围，不是声称当前 hash-only L1 接口已经具备完整执行。当前严格 OutcomeProgram 和 L3 preparation 模块不降低原要求；普通执行能力通过现有可组合层或明确后继接入，不能把严格模块的缺项静默设为已满足。

### 2.2 组件分工及接入方向

| 组件 | 职责与本轮规划的接入点 |
| --- | --- |
| 用户/Agent 入口 | 私有目标输入、方案卡、一次明确确认、查询、取消、必要越界确认；公开 API 与私有上下文分离 |
| 结果与损失合约编译 | 从目标生成状态谓词、里程碑、期限、预算、验收以及事前约定赔付条款；不生成虚假报价或资本 |
| 通用模型执行器 | 调用已启用工具完成理解与探索；产出可追踪的 proposal/Attempt；可替换、可中止、可恢复 |
| 资源发现与临时形成 | 并行发现供给；获取报价、ETA、接受与容量；为这张订单选择真实可执行的组合 |
| 买方身份与交易路径选择 | 在现有形成器和 Node 内选择本单游客会话、获准的采购关系或确有必要的本人授权；绑定受益人、资源权利人及本单交易，不另造账号平台或调度器 |
| 状态规划与恢复决策 | 在实际时间、成本、容量、依赖和授权内计算方案；继续编译到既有 OutcomeProgram |
| 持久生产运行时 | 调度、超时唤醒、重启续跑、对账、重复事件处理、恢复、取消与资源清理 |
| Edge / Resource Node | 持有本地凭证，执行原生接口和获授权设备操作，输出真实回执；不集中转存用户秘密 |
| 独立验收与责任 | 观察联合状态和持续窗口，区分未知/失败/成功，管理恢复义务、异议与后续责任 |
| 风险与外部资本接入 | 预测损失、比较恢复成本、形成承保资料、取得真实报价和绑定、准备索赔及确认到账 |
| 数据与学习网络 | 完整记录候选、选择、失败、取消、恢复、损失和赔款；按授权形成研究与可验证改进 |

这是现有组件的产品化与接线计划，不是建设第二个 orchestrator、第二套身份系统或独立保险平台。

## 4. 新接入的核心：结果合约、损失与资金不是同一个字段

以下记录与字段是**待实现或待接入的设计**，不因写入计划而成为已上线能力。

### 4.1 一个结果定义，四类经济记录

| 记录 | 内容 | 来源与约束 |
| --- | --- | --- |
| 事前约定赔偿义务 | 触发事件、约定金额或公式、上限、币种、支付期限、责任主体 | 用户及承责方接受的合同，不是已发生损失 |
| 预测损失与干预估计 | 失败概率、损失区间、恢复效果、相关暴露、未知参数 | 模型版本、适用任务域与数据依据；预测不写成事实 |
| 事后实际损失 | 实际成本、经约定方式认定的机会损失、暴露窗口与争议状态 | 证据及认定过程，含零损失和未决损失 |
| 实际退款/赔款/追偿 | 应付、已付、到账、退款、供应方返还、保险赔付与未追回余额 | 支付和资本方回执；各项分账，不重复冲抵或隐藏缺口 |

现有 `outsider-loss-exposure-evidence.js` 主要处理事后损失/暴露研究，不能把事前约定赔偿直接塞入已观察损失。金额使用币种与精确最小货币单位，公式注明单位、上限、去重和汇率政策。

### 4.2 合同在任务开始前明确什么

- 目标状态、多个状态必须同时成立的条件、里程碑与持续有效窗口。
- 形成截止时间、交付截止时间、最晚恢复触发时间；不把“最晚形成”误用作“最早验收”。
- 商品/资源费用、执行服务费用、恢复预算、保障相关费用分别列明；总价可统一展示，但不是所有费用都称保费。
- 损失项目：直接支出、替代成本、按约定方法计量的停工/机会损失、用户声明的主观价值。声明、估计和对方接受的责任必须分别保留。
- 赔付模式：约定金额，或事前冻结公式后按实际情况计算；触发、证据、例外、免赔、上限和支付时间都明确。
- 谁先对用户负责、谁最终承担资金、谁认定争议；用户不应被迫逐一向模型、商家和物流追责。
- 在用户变更目标、延期、取消或外部条件变化时，采用明确后继版本；不能事后缩小已接受责任。

不以“模型已经穷尽全部隐性损失”作为承诺前提。合同可以明确约定如何补偿，但不能证明未来所有实际损失都不会超出估计。

### 4.3 生命周期分开，避免假闭环

执行状态沿用既有生命周期，产品投影至少区分：`形成中 / 执行中 / 恢复中 / 已验收 / 未达成 / 结果未知 / 已取消`。

保障状态单独表示：`未选择保障 / 资料准备 / 仅估价 / 已报价未绑定 / 绑定中 / 已生效 / 已到期或依法终止 / 索赔中 / 应付已确定 / 已到账 / 有争议`。

“未达成＋已到账”不是“已交付”；“已报价”不是“已承保”；“支付请求已接受”不是“赔款到账”。成功交付后仍可能有持续观察或未关闭义务。

L3 对外发出承诺前，要把当前合约、实际供给与恢复权利、验收、当前权限、实际生效的保障或资金、支付及争议路径绑定在一起。平台可以原子化记录自己的承诺决定，但不能假装多个外部系统支持全局原子事务；绑定失败、超时和效果未知必须对账或补偿，不能盲目重复付款、预订或承保。

- **交付物：** 可解释的结果/损失合同、恢复经济比较、资本报价所需输入；当前仍不将影子估计销售为保费。
- **完成门：** 能逐项解释金额从哪里来，分清用户声明、模型预测、双方约定义务、实际损失与实际支付。

**依赖：** 合同设计可从 N1 并行开始；真实校准依赖 N3 的数据。没有真实数据不阻止 N1–N3 的普通执行。

### N5 — 外部资本与赔付基础设施接入

**用户能力：** 对支持的任务得到真实、可生效的保障选项，而不是 Outsider 自行生成的“保险价格”。

- **C：** 复用 institutional-capital / Stage 3 / Stage 4 的语义与证据绑定，接入 partner quote、binding、effective cover、amendment、claim、payment confirmation 和 dispute 生命周期；研究模块不直接变成承保服务。
- **C：** 在对外结果义务与外部保单/担保之间建立覆盖映射，逐项列明赔付原因、限额、期限、免责、免赔、谁先付款和未覆盖余额。不得把只保模型错误的保障解释为任意履约失败都保。
- **P：** 选择首个任务范围和司法辖区，取得专业法律分类与实际合作方；明确 Outsider 的执行方、分销/中介、承诺方等角色。外部保险人、支付方与独立认定者各自承担其约定职能。
- **P：** 将真实 quote/bind 和支付权限接到执行产品；需要账户、付费、主体签署或持牌服务时明确列出依赖，不代替对方同意。
- **R：** 取得一家实际资本/保险合作方对具体支持范围的可执行条款及接入资格，完成其授权的测试或试点链；能证明准备覆盖的责任没有无人承担的缺口。
- **交付物：** 一条可用的外部资本路线、覆盖说明与理赔接线；不是泛泛“未来找保险公司”。
- **完成门：** 真实资格和生效机制可核对；测试保单、合作邮件、报价和正式生效分开报告。法律意见、资本或合作方缺失是此层外部依赖，不是暂停整个产品的理由。

**依赖：** N4 的合同/资料包；早期合作范围调查可并行，承保上线不能先于真实接受。公司级合作不是逐单员工 outreach。

### N6 — 首个资本支持的真实结果订单

**用户能力：** 对支持范围内的一项任务，确认完整费用、权限和失败赔付条款；随后由产品履行，失败时进入已约定的救济路径。

- **C：** 将严格 L3 合同、当前主/备/验收资源、恢复预算、实际资本绑定和支付路径接到同一个 Outcome；保障不旁路原权限与责任要求。
- **C：** 合同/供给/资本准备、绑定和失败补偿形成持久流程；任何对外承诺都有确定主体与可验证版本。承诺后能力丧失进入恢复/赔付/争议，不静默退回“未承诺”。
- **P：** 首个受限试点按每单最大责任和总暴露控制，正式收费、购买资源和赔付都依照明确授权；不得靠下一批保费填补已经无资金支持的承诺。
- **R：** 完成一笔真实生效的资本支持订单，执行至验收或真实符合条款的失败处理。实际赔款需金融回执确认；没有发生合法赔付事件时，明确标记“真实理赔尚未经历”。
- **R：** 理赔连接可用合作方明确授权的测试进行验证，但不得故意造成投保损失、虚报事故或把测试赔付当真实保险事故。测试、授权演练、正常交付和真实索赔分别计数。
- **交付物：** 第一个完整的商业结果合约实例、实际履约记录及适用资金证据。
- **完成门：** 首笔保障真实生效且执行闭环；真实索赔经验作为单独成熟度，不为凑验收制造事故，也不因尚未自然发生索赔而否认成功交付。

**依赖：** N3＋N4＋N5，以及旧严格 L3 profile 的适用要求。若要引入不同保障拓扑，另出正式后继，不能改旧订单。

### N7 — 真实数据驱动的因果、精算与生产改进

**用户能力：** 随真实经验增加，路线、恢复和保障选择逐步改善；不因研究升级而失去已经接受的合同权利。

- **C：** 复用 Episode Data Engine、来源台账、因果干预研究与训练评估框架；为预行动用途重新构建时间正确的特征，隔离含完成后信息的回顾性模型。
- **C：** 按用途分开训练：发现/获取排序，路线/恢复建议，损失/延迟预测。前一种改善不自动批准后一种用途；定价、承保和资金权限仍由各自真实规则决定。
- **P：** 固定关联根分组、训练/校准/留出划分，保留 outcome-blind 随机审查样本；记录数据权利、基线、失效与漂移，支持回滚。源数据不能因导出或训练流入公共投影。
- **R：** 在目标任务域有足够适用的真实证据后，验证至少一种改进。数据不足或未胜出时 `KEEP_BASELINE`，不把模拟、农业保险统计或供应方宣传当 agent 任务定价依据。
- **交付物：** 被明确用途接受的模型版本、可追踪评估与实际效果；不足部分保留研究状态。
- **完成门：** 改善在未参与调参的任务/时间/关联组上成立，且没有隐性增加失败损失或用户/员工介入。研究晋级不自行授予生产行动、训练、价格或资本权限。

**依赖：** 采集从 N1–N4 持续发生；生产模型晋级依赖对应真实数据与批准，不要求等 N6 才能改善非承保功能。

### N8 — 需求汇聚与可复用资源网络

**用户能力：** 更多任务能复用既有可用条件；不同用户、企业和 Agent 共享网络带来的真实交付收益。

2026-09-07 用户确认：不为追求长期护城河跳过基本交付，也不把接口仓库当作供应网络。每次真实履约应能留下可再次使用的交易路线和关系事实；未来条件只有在供应方明确开放后才进入分配。经济优势必须在后续真实订单上表现为可获得的容量、成本、完成率或已承担责任的变化。大厂和其他 agent 也可能积累这些关系，不能以“竞争者一定不做”替代实证。

跨用户可共享的是允许共享的接法、资源条件与关系收益，不是其他人的账户、订单密钥或个人授权。全球入口与局部品类/地区/时间窗口的实际供需密度分开衡量。模型能力提升应提高产品形成/执行能力；更换模型不丢失已经合法取得的资源关系。

- **C：** 履约后自动邀请独立 standing opt-in，记录范围、价格、期限、容量、可撤销条件与责任；邀请不是授权。为可复用能力增加跨订单分配、取消接续和当前容量查询。
- **C：** 订单临时网络仍独立、到期解散；复用的是另行取得的 standing grants、交易条件与能力，不复制旧订单 nonce、授权或预留。共享备份按并发和相关故障配置，不能多单重复占用同一份容量。
- **P：** 用户/机构/owner 节点自助接入，多入口发现与路由；支持经允许的需求聚合和资源调剂。全球接入与本地/品类/时段的供需密度分别衡量。
- **R：** 后续真实订单取得前一批订单促成的可用条件，并验证其真实使用；不是供应方名单变长或“网络成员数”增加。
- **交付物：** 外部接受的复用条件、跨订单分配和新的真实订单；通过持续交易积累网络资产。
- **完成门：** 不依赖员工逐单协调，跨订单复用不牺牲已承诺责任；参与者留下是因为真实交易收益，不是强制入驻或人为扣留数据。

**依赖：** 基础邀请与数据结构可从 N2/N3 开始；经济规模不作为首笔订单的前置条件，也不是可以用固定日期承诺的工程产出。

## 6. 并行工作安排与关键路径

### 三条持续主线

| 主线 | 现在优先做 | 随后衔接 | 不应等待 |
| --- | --- | --- | --- |
| A 产品与生产执行 | N1 入口＋N3 常驻续跑/对账 | 多任务、事件驱动、取消恢复 | 全网接口、自训大模型、保险合作完成 |
| B 真实资源与临时网络 | N2 发现到真实交易/容量 | N3 非数字闭环、N8 自助复用 | BD 团队、卖方专门支持 Outsider、所有 MCP 开放 |
| C 结果合约与数据/资本 | N4 分账、草案、暴露/损失记录 | N5 外部资本、N6 保障试点、N7 验证 | 普通执行不等这条线；正式保障则必须等真实资本条件 |

关键依赖是：N1＋N2 的可用切片使 N3 真实执行成立；N3 的真实记录进入 N4；N4＋N5 支持 N6。N7 的记录与研究、N8 的自愿邀请及接入设计可提前并行，不能把后期规模目标变成早期启动门。

单人加 Agent 的在制工作建议限制为：一个生产内核增量、一个外部接口/任务闭环、一个合同/数据接线。子 Agent 适合独立模块与只读核对，不同时写同一入口，不用并发制造重复外部效果。

### 接下来三个迭代包

**迭代 A：产品自己继续运行。**

- A 线：完成提交/确认到现有 runner 的最小接线，以及常驻 Node 的事件续跑和未知效果对账。
- B 线：把一条真实交易/容量接口接入同一生命周期，确定最短可执行的真实任务切片。
- C 线：建立结果条款草案和四类经济记录，接既有 Episode/Attempt，不收费承保。
- 演示必须是实际运行与可查询任务，不以新增类型文件数量作为完成。

**迭代 B：外部结果闭环。**

- 完成一个非数字任务的真实执行、验收与资源释放；补齐该任务确实需要的下单/预订、回执、取消/恢复接口。
- 在同一内核换第二任务族，检查是否仍依赖研发手动补位。
- 产出真实成本/暴露资料与一个可供资本方理解的完整合约样例。

**迭代 C：可选择的资本保障。**

- 普通执行继续扩展；并行推进专业分类、具体合作范围、真实 quote/bind 和理赔测试。
- 条件成熟时进入 N6；合作周期未知时保持 N5 外部依赖状态，继续 A/B 与 N4/N7，不转回全仓研究。

这里不把工程迭代、外部合作等待和任务自然工期合成一个“30 天”。N0 是有限文档收敛；首个实现迭代后按实际吞吐给出后续开发估算。保险合作、资源 owner 采用与真实交付日期单列，不伪造已确认日历。

## 7. 真实里程碑：从小任务验证复杂系统所需模块

里程碑不强制先购买商业保障，且不以线上/线下划分高低优先级。

| 里程碑 | 真实结果 | 必须覆盖的核心模块 | 不能冒充的完成 |
| --- | --- | --- | --- |
| M1 产品自主数字闭环 | 复用数字交付任务，从用户入口启动并跨中断完成 | 合同、真实接口、持久任务、恢复、外部验收、资源清理、完整费用记录 | 旧数字实验已证明部分链路；新验收补的是不依赖开发对话的产品入口和常驻执行 |
| M2 最小非数字完整订单 | 可选“在明确期限内送达符合规格的杯子”或更短可行的真实任务 | 即时选供给、主/备路线、确切授权、真实订单/预订、现实状态、异常处理、验收 | 不是加入购物车、寄出邮件、收到商家 ACK；本计划不复用旧地址/日期或批准购买 |
| M3 联合状态任务 | 例如“一个小工作位在期限内具备实际可用的空间、网络与设备”，具体任务另行冻结 | 多类资源、至少两个独立参与方、时间/容量依赖、一个现场状态、联合验收和恢复 | 不是把三个完成动作相加；线上采购、部署和设备状态必须共同满足目标 |
| M4 首个保障订单 | 某一已支持任务的结果合约实际生效并执行 | 约定损失、真实 quote/bind、资金责任、验收或合法失败处理 | 保单样例、模拟付款、保险方介绍邮件均不算生效；真实理赔经历单列 |
| M5 网络复用 | 新订单实际使用历史订单促成的 standing 条件 | 单独 opt-in、容量分配、撤销、跨订单经济记录 | 不把同一供应商再次被搜索到算网络资产形成 |

M2 的具体商品不是架构；M3 的办公室示例也不是行业收缩。工厂投产等大目标沿里程碑和资源组合能力逐步扩展，不预先承诺代码具备就能在任意现场执行。

| W06 损失条款与经济分账 | 合同后继、loss-exposure、product data bridge；N4 | 事前赔付草案、预测、实际损失和实付分别可查 |
| W07 首个承保资料包与资本路线 | W06；institutional/Stage 3/4 接口；N5 | 具体任务族、司法辖区、覆盖/缺口与真实对方反馈，未绑定时明确标注 |
| W08 小型联合状态任务 | W01–W05，第二资源类别；N3 | 同一内核调度多方依赖并观察联合状态，无行业专用核心分叉 |

W01–W05 是当前主要工程投入。W06 并行薄接线；W07 不吞掉执行主线；W08 避免长期困在单商品样本。具体新增文件名在实现前按现有模块接口确定，不在计划里预先创造大量空壳模块。

## 10. 验证、度量和报告方式

### 只做与实际能力相关的验证

- 普通改动跑触及路径与相邻模块测试；协议迁移、资金、授权、重复执行风险增加对应检查。文档改动不跑全仓代码测试。
- 每个实现迭代尽量产出一个真实可执行增量或外部事实。不能把测试数量、文件数量、影子数据量当产品完成度。
- 不覆盖被冻结产物；当前活跃代码允许正常修复与重构。新运行有新记录，旧未决任务按原合同处理。
- 真实来源保留时间、版本与适当哈希；原始敏感资料留在受限存储，原始采集文件按 0600 要求处理，不进入公开投影。
- 数据采集使用现有 Episode Data Engine 的范围和队列；只有当前任务缺口需要才新增来源，不恢复无限无关采集或旧每日 loop。

### 每次报告同一组事实

1. 用户新增了什么实际能力；代码/生产/真实各到哪里。
2. 真实调用与回执：来源、时间、任务/Attempt、动作次数、实际费用；失败和效果未知单列。
3. 自动化：用户介入、Outsider 员工介入、外部资源人工行为分别计数。
4. 履约：从提交到形成、从形成到交付、恢复触发至生效的时延；按期限验收与拒绝都保留分母。
5. 经济：资源费、执行费、恢复费、保障费、应赔、实赔、退款/追偿和未覆盖责任。
6. 研究发生时才报告训练样本/暴露、固定划分根、基线、指标、晋级或 `KEEP_BASELINE`；不把历史全量哈希清单重复塞进用户进度。
7. 下一项可执行工作与真正外部依赖。没有变化时简短说明，不重复展示一长串 HOLD。

### 阶段完成不是永久能力保证

某个任务族通过 C/P/R，不代表任意地域、所有 provider 或所有保额自动启用。新的领域和责任有具体适用范围；模型、owner、资金和接口变化可能影响未来报价，但不追溯缩减已生效义务。

## 11. 明确暂缓的工作

- 不建立每单需要员工找资源、回邮件、替用户 checkout 的后台运营系统。
- 不要求先有供应商 marketplace、独占供给或创始人全球 BD 能力。
- 不新建全能调度器、全新身份图或“所有现实动作必须投保”的基础设施。
- 不把新数据审计器、更多影子统计和无关 benchmark 当主要交付。
- 不强制自训模型，不把有事后泄漏的旧特征拿来训练预行动策略。
- 不销售无真实资本支持的保障，不默认自己成为承保公司，也不预先决定收费或赔付金额。
- 不把“市场绝无同类”“大厂绝不会进入”当工程前提。
- 不以首个简单任务为产品边界，也不以“最终要做工厂”作为推迟最小产品的理由。

## 12. 外部资本设计参考与待专业确认事项

以下来自本任务前几轮查阅的官方/专业来源，只用于方案设计，不证明 Outsider 已有合作、资格或可售保障：

- [AirHelp 产品](https://www.airhelp.com/en-int/airpayout/)与[条款](https://www.airhelp.com/en-int/terms/)：现实事件触发现金赔付、由中介连接外部风险承担人的相邻例子；不是通用临时供应网络。
- [Munich Re aiSure](https://www.munichre.com/en/solutions/for-industry-clients/insure-ai.htmlindex_na.html)：AI 表现保障的资本合作例子；不等于全原因任务失败都在承保范围。
- [NAIC 参数型保险说明](https://content.naic.org/insurance-topics/parametric-disaster-insurance)：预定触发/赔付与实际损失可能不一致；合同冻结不消除所有未预见损失。
- [Massachusetts Chapter 175 §2](https://malegislature.gov/Laws/GeneralLaws/PartI/TitleXXII/Chapter175/Section2)及[§3](https://malegislature.gov/Laws/GeneralLaws/PartI/TitleXXII/Chapter175/Section3)：保险定义与授权要求的首个所在地参考；全球业务不自动共享一种法律资格。

正式商业上线前，需要针对实际合同、销售地区、赔付主体、分销角色和资金结构取得专业判断。提高费用、改叫“任务费”、引用法律或实现 schema 都不能替代这些事实。此依赖属于 N5/N6，不阻塞 N1–N4 的合规普通产品工程。

## 13. 本版结论

近期目标是让 Outsider 本身完成真实任务，而不是让开发 Agent 代办；中期目标是对明确范围提供实际有资金支持的结果合约；长期目标是让订单积累可复用的资源条件、可信的损失经验与跨入口需求网络。

顺序不反转：**通用产品可用 → 临时网络真实执行 → 结果/损失合约接入 → 外部资本支持的承诺 → 真实反馈改进与网络积累。** 记录和薄接线可以并行，真实承诺不提前冒领。
