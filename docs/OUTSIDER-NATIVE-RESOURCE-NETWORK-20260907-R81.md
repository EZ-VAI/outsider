# r81 — 通用原生资源节点进入原产品，现实门仍未完成

2026-09-07 UTC，承接 r79；r80 是本轮中间部署，r81 增加正常异步履约。**本轮是 N1/N2/N3 的代码与部署增量，不是新真实商业闭环，也没有完成四门。**

## 实际改动与意义

此前主产品只能执行少数内置任务类型；增加一个资源类别经常需要新增整套编译片段和执行组件。现在增加 `CONNECTED_NATIVE_RESOURCE_V1`，已接原 `OPEN_OUTCOME_V1`、资源图、一次确认、原 `OutcomeProgram`、常驻队列和工作台附件。

一次平台/资源连接声明其已有 HTTP/JSON 接口的请求参数与响应含义，随后每张任务自动执行：

1. 并行取得本单主、备路线的当前条款：价格、完成时间、报价有效期、责任条款及原生引用。
2. 用户确认原提案后，分别取得两条路线的原生容量接受；没有把报价或本地配置当成已预留。
3. 原图前序结果通过后，才提交本节点的真实资源动作。
4. 对异步工作，接受排队只完成“提交动作”；原任务继续等原生完成状态，不进入下游节点、不重发执行。
5. 第三个接口核对同一预约/执行引用及本节点的验收合约；最后再做整图当前状态验收。
6. 按原义务关闭资源占用。释放未使用容量不等于撤销已经交付的结果。

请求模板可以直接表达 REST 或 MCP `tools/call` 的 JSON 信封。响应采用原生 JSON Pointer 与明确枚举映射，不要求供应方返回 Outsider 字段、开户入驻或重写 API。Node 连接持有地址、凭证引用和解释规则；每单输入不携带任意 URL 或密钥。

**用人话说：新能力是“把一组已接通的资源接口作为可重复调用的任务积木”，不是又写死一个购物网站。** 采购、服务、获授权资产动作都可以是积木所表示的手段，但必须已有能证明其真实语义的连接。

## 不得扩大解释的范围

- 当前新目录 `GET /v1/resource-contracts` 返回 **0 条已配置资源网络**。没有伪装成已发现、已连接或已接受的真实供应方。
- 网络模板目前仍须一次性连接主、备及验收接口；本轮没有实现“从空白供应表自动找到未知接口并赋予正确执行语义”。开放发现组装实际连接仍是 N2 主缺口。
- 目前使用已批准的公开、标量输入，零费用操作。个人数据、付费交易、支付工具和资本承诺没有开放。不能通过把价格映射成 0 来接付费接口。
- 接口必须具有相应的报价、预留、执行、状态和释放语义；普通网站、一个 URL 或 API 文档不会自动成为执行器。没有真实预留功能的提供方不能伪装成预留路线。
- 已配置的三个提供方标识/源站不同，不自动证明法律主体或最终所有权独立。当前第三方验收也是连接声明的具体合约，不是对任意自然语言结果的普遍证明。
- 备用自动执行仅覆盖原生明确报告 `FAILED_NO_EFFECT` 的分支；未知效果、已发生动作后的修复仍需对应的真实恢复协议。不能盲目重复预订或设备动作。
- 跨节点传入本次原生动作输出尚未扩展至任意资源参数；既有 `executionBindings` 的类型范围不变。
- 用户目前可通过原 API/公开资源请求附件引用连接；不是已完成普通用户自然语言自助选择所有资源的体验。
